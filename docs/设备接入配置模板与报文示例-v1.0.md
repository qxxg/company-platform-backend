## 1. 接入总览

```text
设备主板
 ├─ MQTT（首选）：publish 到 device/{deviceNo}/...
 ├─ CoAP：PUT 到 /device/{deviceNo}/...
 ↓
接入层（MQTT Broker / CoAP 服务）
 ↓ 鉴权、验签、防重放、幂等
消息队列（Redis Stream / Kafka / RabbitMQ）
 ↓ 异步消费
 ├─ 订单作业数据 → MySQL（按 order_no 唯一，后推覆盖前推）
 ├─ 自检/异常/状态 → Apache IoTDB（时序）
 └─ 订单图片 → 对象存储/文件服务 → OCR → 订单号精准匹配 → 回写订单进度
```

**核心规则：**

1. 设备上报数据分为：订单作业数据（每 10 秒）、订单图片（一条订单仅一次）、状态/心跳、自检、异常/故障。
2. 一台设备同一时间只处理一个订单；订单作业数据以 `orderNo` 关联订单。
3. 所有参数（地址、端口、Topic、频率、图片限制、OCR 阈值、保留周期等）均可通过配置文件手动配置；系统初始化提供下文的默认值。
4. 报文统一 JSON，图片走 HTTP 上传或 base64（可配置）。

## 2. 配置文件模板

推荐文件：`config/application-iot.yml`（Spring Boot 风格示例，字段名可按开发框架调整，语义不变）。

```yaml
# ============================================================
# 设备数据接入配置（初始化默认值，按现场情况修改）
# 配套主文档 V1.4 · 6.8.8
# 说明：${ENV} 形式建议由环境变量/密钥管理注入，不写死在文件
# ============================================================
iot:
  enabled: true

  # ---------- MQTT Broker ----------
  mqtt:
    enabled: true
    host: 127.0.0.1          # 部署位置：内网/公网地址均可配置
    port: 1883               # TLS 时使用 8883
    tls-enabled: false       # 生产建议 true
    tls-cert-path: /opt/app/certs/server.pem
    tls-key-path: /opt/app/certs/server.key
    ca-cert-path: /opt/app/certs/ca.pem
    ws-enabled: false        # 是否启用 WebSocket（浏览器调试用）
    qos: 1
    keep-alive-seconds: 60
    # 鉴权：onekey（一机一密）| cert（证书）；禁止匿名
    auth-mode: onekey
    anonymous-enabled: false

  # ---------- CoAP 服务 ----------
  coap:
    enabled: true
    host: 0.0.0.0
    port: 5683               # DTLS 时使用 5684
    dtls-enabled: false      # 生产建议 true
    dtls-psk-enabled: true
    max-payload-kb: 64

  # ---------- Topic / 资源路径模板 ----------
  topic:
    # {deviceNo} 由设备编号替换
    order: device/{deviceNo}/order
    image: device/{deviceNo}/image
    status: device/{deviceNo}/status
    selfcheck: device/{deviceNo}/selfcheck
    fault: device/{deviceNo}/fault
    # 下行（平台 → 设备）
    ack: server/{deviceNo}/ack
    cmd: server/{deviceNo}/cmd
    coap-path-prefix: /device/{deviceNo}

  # ---------- 报文 ----------
  payload:
    version: v1              # 当前报文版本
    timestamp-unit: millis   # 毫秒时间戳
    max-size-kb: 128         # 单条非图片报文上限
    sign-algorithm: HmacSHA256
    replay-window-seconds: 120   # 时间戳偏差超过该值视为重放
    dedupe-window-seconds: 300   # 按 deviceNo+seq 去重窗口

  # ---------- 图片 ----------
  image:
    transport: http          # http | base64 | chunk
    http-upload-path: /api/iot/image/upload
    max-size-mb: 5
    allowed-formats: [jpg, jpeg, png]
    jpeg-quality-hint: 80
    storage-type: local      # local | oss | minio
    local-dir: /data/iot/images
    oss-bucket: company-iot-images
    retention-days: 1095     # 默认 3 年；0 = 永久

  # ---------- OCR ----------
  ocr:
    endpoint: http://127.0.0.1:8000/ocr
    connect-timeout-seconds: 3
    read-timeout-seconds: 10
    confidence-threshold: 0.90   # 低于阈值转人工
    retry-times: 3
    retry-interval-seconds: 30
    # 订单号归一化：去掉空格/换行；可选前缀校验
    order-no-prefix: "SO"
    order-no-pattern: "^SO[0-9]{12}$"   # 示例：SO+yyyyMMdd+4位流水

  # ---------- Apache IoTDB ----------
  iotdb:
    host: 127.0.0.1
    port: 6667
    username: root
    password: ${IOTDB_PASSWORD}
    database: root.device
    session-pool-size: 4
    batch-size: 500
    flush-interval-ms: 1000
    retention-years: 3       # 时序数据保留周期

  # ---------- 消息队列 ----------
  queue:
    type: redis-stream       # redis-stream | kafka | rabbitmq
    redis:
      host: 127.0.0.1
      port: 6379
      password: ${REDIS_PASSWORD}
      stream-key: iot:stream:report
      consumer-group: iot-consumer
    kafka:
      bootstrap-servers: 127.0.0.1:9092
      topic: iot-report
    rabbitmq:
      host: 127.0.0.1
      port: 5672
      queue: iot.report.queue

  # ---------- 上报频率（可按设备型号覆盖） ----------
  frequency:
    order-seconds: 10        # 订单作业数据：默认 10 秒
    status-seconds: 30       # 心跳/状态
    selfcheck-cron: "0 0 3 * * ?"   # 自检：启动时 + 每天 03:00
    offline-threshold-periods: 3    # 3 个周期无数据判离线
    device-model-overrides:
      # 示例：某型号 15 秒上报
      # "MODEL-X1": { order-seconds: 15 }

  # ---------- 离线补传与时间同步 ----------
  offline:
    resend-enabled: true
    device-cache-max-rows: 1000     # 设备端缓存上限
    device-cache-ttl-hours: 24
    server-accept-late-seconds: 86400  # 服务端接受迟到的补传（仍校验时间戳与签名）
  timesync:
    ntp-server: ntp.aliyun.com
    allowed-skew-seconds: 30        # 设备与服务器时间偏差告警阈值
    sync-interval-hours: 24

  # ---------- 安全 ----------
  security:
    rate-limit-per-device-per-minute: 120
    ip-allowlist-enabled: false
    ip-allowlist: []
    cmd-enabled: true               # 是否允许下行指令（校时/查询）

  # ---------- 数据保留 ----------
  retention:
    order-report-days: 0            # 0 = 永久/按年归档
    order-report-keep-history: false  # 是否保留每次推送历史（默认只留最新）
    image-days: 1095
    iotdb-years: 3
```

**配置原则：**

- 初始化默认值即可启动；现场按网络与设备情况修改，不需改代码。
- 修改配置需要运维/管理员权限并记录变更；建议按环境（dev/test/prod）分文件。
- 密钥、密码通过环境变量或密钥管理注入，不直接写在配置文件中。

## 3. Topic 与资源路径定义

| 用途 | MQTT Topic | CoAP 路径/方法 | 方向 | 频率 | 存储 |
|---|---|---|---|---|---|
| 订单作业数据 | `device/{deviceNo}/order` | `PUT /device/{deviceNo}/order` | 上行 | 默认 10 秒 | MySQL（按订单覆盖） |
| 订单图片 | `device/{deviceNo}/image` | `PUT /device/{deviceNo}/image` | 上行 | 每订单一次 | 对象存储 + 图片表 |
| 状态/心跳 | `device/{deviceNo}/status` | `PUT /device/{deviceNo}/status` | 上行 | 默认 30 秒 | IoTDB |
| 自检 | `device/{deviceNo}/selfcheck` | `PUT /device/{deviceNo}/selfcheck` | 上行 | 启动 + 每日 | IoTDB |
| 异常/故障 | `device/{deviceNo}/fault` | `PUT /device/{deviceNo}/fault` | 上行 | 发生时 | IoTDB |
| 平台回执 | `server/{deviceNo}/ack` | CoAP 响应报文 | 下行 | 每条上行 | 不落库 |
| 平台指令 | `server/{deviceNo}/cmd` | `GET /device/{deviceNo}/cmd`（可选） | 下行 | 按需 | 指令日志 |

**规则：**

- MQTT QoS 建议 1（至少一次），服务端按 `deviceNo + seq` 幂等去重。
- CoAP 建议使用 CON（可确认）消息；响应携带回执码。
- 设备订阅 `server/{deviceNo}/ack` 与（可选）`server/{deviceNo}/cmd`。
- Topic/路径模板均可配置，支持不同型号设备映射到同一语义。

## 4. 公共报文规范

### 4.1 报文信封

```json
{
  "version": "v1",
  "msgType": "order",
  "deviceNo": "DEV-0001",
  "orderNo": "SO202610190001",
  "timestamp": 1760832000000,
  "seq": 10231,
  "nonce": "8f2c1a9b4e",
  "sign": "3f4a...（HMAC-SHA256 十六进制小写）",
  "payload": { }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| version | string | 是 | 报文版本，默认 `v1` |
| msgType | string | 是 | `order` / `image` / `status` / `selfcheck` / `fault` / `cmd_ack` |
| deviceNo | string | 是 | 设备编号（系统内唯一，设备档案已登记） |
| orderNo | string | 否 | 订单号；与订单相关报文必填 |
| timestamp | long | 是 | 毫秒时间戳 |
| seq | long | 是 | 设备内单调递增序号，用于幂等去重 |
| nonce | string | 是 | 随机串（16 位以内），配合时间戳防重放 |
| sign | string | 是 | 签名，见 4.2 |
| payload | object | 是 | 按 msgType 定义 |

### 4.2 签名算法

```text
sign = HMAC-SHA256(
  secret,
  deviceNo + "|" + msgType + "|" + timestamp + "|" + nonce + "|" + payloadJsonCompact
)
```

- `secret`：设备一机一密密钥（或证书私钥对应的 PSK），服务端按 deviceNo 查询。
- `payloadJsonCompact`：payload 的紧凑 JSON（无多余空格，key 按字典序排序）。
- 输出：十六进制小写。
- 服务端校验：签名一致、时间戳偏差 ≤ `replay-window-seconds`、`deviceNo+seq` 未在去重窗口内出现过。

### 4.3 服务端回执

平台处理完上行报文后，向 `server/{deviceNo}/ack` 发布（CoAP 为响应体）：

```json
{
  "version": "v1",
  "msgType": "ack",
  "deviceNo": "DEV-0001",
  "orderNo": "SO202610190001",
  "timestamp": 1760832000350,
  "payload": {
    "seq": 10231,
    "code": 0,
    "message": "ok",
    "matched": true,
    "imageId": "IMG202610190001",
    "serverTime": 1760832000350
  }
}
```

| code | 含义 | 设备端动作 |
|---|---|---|
| 0 | 成功 | 无需处理 |
| 1001 | 报文格式错误 | 修正后重发（最多 3 次） |
| 1002 | 不支持的 msgType | 检查固件版本 |
| 1003 | 报文超限 | 压缩/拆分后重发 |
| 2001 | 鉴权失败 | 检查密钥/证书，停止重试并告警 |
| 2002 | 签名错误 | 检查签名算法与 payload 排序 |
| 2003 | 重放/重复 | 忽略（不重发） |
| 2004 | 设备已停用/未登记 | 联系管理员 |
| 3001 | 订单不存在/未匹配 | 继续按周期上报，等待人工处理 |
| 3002 | 订单已关闭 | 停止该订单上报 |
| 4001 | OCR 识别失败 | 等待平台人工处理 |
| 4002 | 图片超限 | 压缩到限制内重新上传（每条订单一次机会） |
| 4003 | 图片重复 | 忽略 |
| 5001 | 服务端异常 | 按指数退避重试 |

### 4.4 通用约定

- 长度单位一律为 **米**，设备上报保留 3 位小数；业务单据与金额计算按长度 2 位小数截取，设备数据仅作进度参考。
- 金额不在此协议内传输。
- 时间一律为毫秒时间戳（UTC+8 展示由平台处理）。
- 字段缺省表示未知，不得用 0 代替“未知”以外的语义；数值型统一 Number。
- 设备端重发必须携带原始 timestamp/seq，服务端幂等处理。

## 5. 消息类型定义与示例

### 5.1 order：订单作业数据（每 10 秒，覆盖式）

**payload 字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| workOrderNo | string | 否 | 工单号（设备端如无则空） |
| status | string | 是 | `idle` / `running` / `paused` / `finished` |
| printedLengthMeter | decimal | 是 | 累计已打印长度（米） |
| progressMeter | decimal | 是 | 订单累计完成长度（米） |
| progressPercent | decimal | 否 | 完成百分比（0–100） |
| inkUsageMl | decimal | 是 | 累计耗墨量（毫升） |
| inkDeltaMl | decimal | 否 | 本次增量耗墨量 |
| remainingMinutes | int | 否 | 预估剩余时间（分钟） |
| speedMeterPerHour | decimal | 否 | 当前速度（米/小时） |
| widthMeter | decimal | 否 | 当前门幅（米） |
| passCount | int | 否 | 已打印遍数 |
| deviceState | string | 否 | 设备运行状态快照 |
| errorCode | string | 否 | 当前异常码（正常为空） |
| imageUploaded | boolean | 否 | 本订单图片是否已上传（首次推送 true） |
| printedAt | long | 否 | 本次数据对应的打印时间 |

**示例：**

```json
{
  "version": "v1",
  "msgType": "order",
  "deviceNo": "DEV-0001",
  "orderNo": "SO202610190001",
  "timestamp": 1760832000000,
  "seq": 10231,
  "nonce": "8f2c1a9b4e",
  "sign": "3f4a9c...",
  "payload": {
    "workOrderNo": "WO202610190001-01",
    "status": "running",
    "printedLengthMeter": 125.5,
    "progressMeter": 125.5,
    "progressPercent": 62.75,
    "inkUsageMl": 320.4,
    "inkDeltaMl": 2.1,
    "remainingMinutes": 45,
    "speedMeterPerHour": 38.2,
    "widthMeter": 1.6,
    "passCount": 1,
    "deviceState": "printing",
    "errorCode": "",
    "imageUploaded": true,
    "printedAt": 1760831998000
  }
}
```

**服务端处理：**

- 以 `order_no` 为唯一键 upsert，最新一次覆盖历史（默认不保留历史，配置 `keep-history` 时另存快照表）。
- 回写订单/工单进度、耗墨量、预估剩余时间；触发交期预警判断。
- 若订单号未匹配（OCR 未完成/失败），数据暂存 `iot_order_report_staging`，OCR 匹配成功后归位。

### 5.2 image：订单图片（每订单一次）

**方式 A（推荐）：图片元数据 + HTTP 上传**

MQTT 元数据报文：

```json
{
  "version": "v1",
  "msgType": "image",
  "deviceNo": "DEV-0001",
  "orderNo": "SO202610190001",
  "timestamp": 1760832001000,
  "seq": 10232,
  "nonce": "ab77c001",
  "sign": "9d1c...",
  "payload": {
    "fileName": "SO202610190001.jpg",
    "format": "jpg",
    "sizeBytes": 348512,
    "width": 1600,
    "height": 1200,
    "hash": "sha256:9f2a...",
    "uploadUrl": "http://platform:8080/api/iot/image/upload"
  }
}
```

HTTP 上传（multipart/form-data）：

```bash
curl -X POST "http://platform:8080/api/iot/image/upload" \
  -F "deviceNo=DEV-0001" \
  -F "orderNo=SO202610190001" \
  -F "timestamp=1760832001000" \
  -F "nonce=ab77c001" \
  -F "sign=9d1c..." \
  -F "file=@SO202610190001.jpg"
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "imageId": "IMG202610190001",
  "duplicated": false,
  "ocrQueued": true
}
```

**方式 B：base64 内嵌**（图片较小、带宽可控时，配置 `transport: base64`）

```json
{
  "version": "v1",
  "msgType": "image",
  "deviceNo": "DEV-0001",
  "orderNo": "SO202610190001",
  "timestamp": 1760832001000,
  "seq": 10232,
  "nonce": "ab77c001",
  "sign": "9d1c...",
  "payload": {
    "format": "jpg",
    "imageBase64": "/9j/4AAQSkZJRg..."
  }
}
```

**规则：**

- 一条订单图片只上传一次；服务端按 `order_no`（或图片 hash）去重，重复上传返回 `4003`/`duplicated: true`。
- 图片上限默认 5 MB；超限拒绝（`4002`），设备压缩后重传一次。
- 上传成功后进入 OCR 队列；OCR 结果回写订单。

```json
  "orderNo": "SO202610190001",
  "timestamp": 1760832100000,
  "seq": 10240,
```

平台 → 设备：

```json

  "timestamp": 1760832200000,
  "payload": {
    "cmdId": "CMD20261019001",
    "cmd": "sync_time",
    "params": { "serverTime": 1760832200000 }
  }
}
```

设备 → 平台：

```json
{
  "version": "v1",
  "msgType": "cmd_ack",
  "deviceNo": "DEV-0001",
  "timestamp": 1760832201000,
  "seq": 10241,
  "nonce": "b77102",
  "sign": "6cd1...",
  "payload": {
    "cmdId": "CMD20261019001",
    "result": "ok",
    "message": "time synced"
  }

```

支持指令建议：`sync_time`、`query_status`、`reboot`、`set_params`（按需扩展）。

## 6. 存储映射

### 6.1 MySQL：订单作业数据（按订单唯一）

```sql
CREATE TABLE iot_order_report (
  id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
  order_no            VARCHAR(32)  NOT NULL COMMENT '系统订单号',
  device_no           VARCHAR(32)  NOT NULL COMMENT '设备编号',
  work_order_no       VARCHAR(32)  NULL,
  status              VARCHAR(16)  NULL COMMENT 'idle/running/paused/finished',
  printed_length_meter DECIMAL(12,3) NULL,
  progress_meter      DECIMAL(12,3) NULL,
  progress_percent    DECIMAL(5,2)  NULL,
```

## 7. OCR 识别与匹配流程

```text
图片入库 → OCR 服务识别
 → 文本归一化（去空格/换行、大写、去噪）
 → 订单号精准匹配（完全一致；可配置前缀/正则校验）
 ├─ 置信度 ≥ 阈值且匹配成功 → 绑定 deviceNo+orderNo → 回写订单进度 → 状态 matched
 └─ 置信度低 / 匹配失败 → 状态 failed → 进入“OCR 待确认”页面 → 人工选择订单 → 状态 processed
```

**订单号规范（必须与设备打印图片一致）：**

- 格式：`SO` + `yyyyMMdd` + 4 位流水，如 `SO202610190001`。
- 图片版式：建议黑体/等宽字体，字号不小于图片宽度的 1/20（或 ≥24px），固定位置（左上角或底部条），黑字白底，避免图案/水印遮挡。
- 分辨率建议 ≥300dpi；倾斜角度 ≤5°；光照均匀。
- 订单号在图片上只出现一次主标识，避免多订单号干扰（需要时以主标识为准并配置区域识别）。

**OCR 服务接口（内部）：**

```http
POST /ocr
Content-Type: multipart/form-data
file: <image>
```

```json
{
  "code": 0,
  "text": "SO202610190001",
  "confidence": 0.97,
  "box": [120, 80, 640, 140]
}
```

**人工处理规则：**

- 待确认列表显示：图片、识别值、置信度、设备、上报时间、候选订单（按相似度推荐）。
- 人工选择正确订单后：回写图片匹配关系、归位暂存的订单作业数据、记录处理人/时间。
- 连续失败或图片损坏可标记“无需处理”并记录原因。

## 8. 设备端行为规范（给主板/固件厂商）

| 阶段 | 行为 |
|---|---|
| 启动 | 连接网络 → 校时（NTP 或平台指令）→ 连接 Broker/CoAP → 上报 status + selfcheck |
| 待机 | 每 30 秒上报 status（心跳）；保持订阅 ack（与 cmd） |
| 订单开始 | 操作员在设备端选择/扫描订单号 → 打印订单图片（含订单号）→ 首次 order 数据携带 imageUploaded=true 并上传图片 |
| 订单进行 | 每 10 秒上报 order 数据（进度、耗墨量、预估剩余时间、速度等）；图片不再重复推送 |
| 订单结束 | 上报 status=finished 的 order 数据；停止该订单上报 |
| 异常 | 立即上报 fault（含 faultCode/级别/时间）；恢复后再上报一条（含 recoveredAt） |
| 断网 | 本地缓存未发送数据（上限默认 1000 条/24 小时）；恢复后按原 timestamp/seq 补传 |
| 重试 | 未收到 ack 或收到 1001/1003/5001 时，按 5 秒/15 秒/60 秒退避重试；2001/2002 停止重试并本地告警 |
| 时间 | 所有 timestamp 为毫秒；与服务器偏差 >30 秒时先校时再上报或标记 |

**带宽建议：**

- 图片优先 HTTP 上传（避免占用 MQTT 通道）；JPEG 质量 80 左右，限制 5 MB 内。
- 订单数据单条报文建议 < 2 KB；避免在 order 报文内重复携带图片。
- 多台设备同一网络时，错峰上报不做强制要求，由服务端队列削峰。

## 9. 安全要求

| 项目 | 要求 | 配置项 |
|---|---|---|
| 鉴权 | 一机一密（deviceNo + secret）或证书；禁止匿名 | `security.auth-mode` / `anonymous-enabled` |
| 传输 | 生产启用 MQTT over TLS / CoAP over DTLS | `mqtt.tls-enabled` / `coap.dtls-enabled` |
| 防重放 | timestamp + nonce + replay-window 校验 | `payload.replay-window-seconds` |
| 防篡改 | HMAC-SHA256 签名 | `payload.sign-algorithm` |
| 幂等 | deviceNo+seq 去重 | `payload.dedupe-window-seconds` |
| 限流 | 每设备每分钟消息数限制 | `security.rate-limit-per-device-per-minute` |
| 报文限制 | 非图片报文大小上限 | `payload.max-size-kb` |
| 密钥管理 | 支持禁用/吊销/轮换；泄露立即更换 | 设备档案 + 配置 |
| 接入审计 | 鉴权失败、异常频率、IP 变化记录日志 | 平台侧 |

## 10. 端到端示例时序

```text
1  设备启动
2  → status（online=true, workState=idle）
3  → selfcheck（items...）
4  操作员选择订单 SO202610190001，设备打印订单图片
5  → image 元数据 + HTTP 上传图片（每条订单仅一次）
6  平台 OCR 识别 → 订单号精准匹配成功 → 图片状态 matched
7  → order（首次，imageUploaded=true, progress=0）
8  → 平台 upsert 订单作业数据 → 订单进度页显示
9  → 每 10 秒 order（progress/ink/remaining 持续覆盖）
10 → fault（E-1023 error）→ 平台告警 → 设备管理员处理
11 → fault（同一 code + recoveredAt）→ 告警恢复
12 → order（status=finished）→ 订单进度 100%
13 → status（workState=idle，等待下一订单）
14 断网期间：设备缓存 order；恢复后按原始 timestamp/seq 补传，平台幂等去重
```

### 13.2 常见问题排查

| 现象 | 排查方向 |
|---|---|
| 设备连不上 Broker | 地址/端口、TLS 开关、防火墙、鉴权密钥 |
| ack 一直 2002 | 签名算法、payload 紧凑排序、secret 是否正确 |
| ack 2003 频繁 | 设备 seq 重复、时间戳过旧、重复补传 |
| OCR 匹配失败 | 图片清晰度、订单号字体/版式、是否使用了新订单号规则 |
| 订单数据不更新 | 订单号是否匹配、设备是否绑定该订单、是否被覆盖为旧数据 |
| IoTDB 无数据 | 测点路径、数据库权限、批量写入配置 |
| 图片未上传 | 图片大小超限、网络带宽、上传地址配置 |
