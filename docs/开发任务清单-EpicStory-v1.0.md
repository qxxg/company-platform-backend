## 1. 使用说明

- 优先级：**P0 上线必备 / P1 管理深化 / P2 后续扩展**。
- 估算单位：**人日**（粗略量级，用于排期参考，误差 ±30%）。
- 每条 Story 的“验收要点”为最小验收标准，详细用例由测试基于主文档“验收要点”与页面字段说明补充。
- 状态机、金额档位、权限矩阵为跨 Epic 依赖，先行冻结。
- 金额一律以 **分** 存取，截取不四舍五入；长度/损耗率保留 2 位小数，单价保留 4 位小数。

## 2. 前提与团队假设

| 角色 | 人数 | 说明 |
|---|---|---|
| 产品/需求 | 1 | 负责确认与验收 |
| UI/原型 | 0.5 | 前期集中，后期支持 |
| 后端 | 3 | Java/Spring 或其他栈均可 |
| 前端 | 2 | PC Web（Vue/React 任选） |
| 测试 | 1 | 功能 + 接口 + 设备联调 |
| 实施/运维 | 0.5–1 | 部署、配置、培训、试点 |

**技术前提：** MySQL 主库 + Redis；Apache IoTDB 时序库；MQTT Broker（EMQX 等）+ CoAP 服务；对象存储/文件服务；OCR 服务（内部部署或自研调用）；全部部署支持内网，对外仅暴露 HTTPS 入口。

## 6. 关键路径与风险

**关键路径：** EP-01 → EP-02 → EP-03/04 → EP-06 → EP-07 → EP-09 → EP-10 → EP-11 → UAT → 试点。

| 风险 | 影响 | 应对 |
|---|---|---|
| 需求变更（大屏位置、打印模板、跟进记录必填等页面项未决） | 返工 | 每迭代冻结范围；已确认的信用/合同/精度/期初/组织/访问方式固定实现 |
| 设备厂商配合不及时（固件/版式/联网） | 设备平台延期 | 尽早提供《设备接入配置模板与报文示例》；准备模拟器 |
| OCR 识别率不足 | 订单匹配失败 | 统一订单号版式；置信度阈值；人工待确认兜底 |
| 权限矩阵复杂（工厂隔离+字段权限） | 用例量大 | 用真实组织填一版走查；自动化权限用例 |
| 材料成本口径数据质量 | 毛利不准 | 采购入库强制字段校验；上线后首月盘点校对 |
| 并行工作过多导致联调冲突 | 集成问题 | 每迭代留联调窗口；接口先行冻结 |

## 7. 测试与验收要点

1. **金额专项**：分存储、截取不四舍五入、长度/损耗率 2 位小数、单价 4 位小数、跨单据汇总一致。
2. **权限专项**：工厂隔离、本人客户、字段脱敏、越权接口拦截、权限变更即时生效。
3. **队列专项**：并发排产、FIFO、插队审批、拆分并行、队列预计时间。
4. **库存专项**：出入库一致性、调拨在途、盘点差异、并发扣减、成本口径。
5. **财务专项**：核销/反核销、部分收付款、账龄、红冲、对账差异；信用占用口径、逾期 30 天阻断、订单必须关联已录入合同。
6. **设备专项**：MQTT/CoAP 接入、断线重连、离线补传、幂等去重、图片仅一次、OCR 匹配、时序查询、配置生效。
7. **性能**：设备 10 秒高频上报（模拟 N 台并发）、订单/库存并发、报表大数据量。
8. **安全**：HTTPS、鉴权、防重放、导出留痕、备份恢复演练。
9. **UAT**：用 2–3 个真实客户/订单走端到端；试点工厂按验收清单签署。

**完成定义（DoD）：** 代码评审 + 单元/接口测试通过 + 权限用例通过 + 文档更新 + 产品验收 + 可部署包。
